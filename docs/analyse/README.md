## 一、目录定位与使命

本工作区旨在沉淀关于 Miyu 项目（超低常驻、高可靠 Rust Agent 架构）的系统性技术洞察、架构审计、性能瓶颈分析以及长程演进改进建议。

不同于即时性的功能补丁或临时性的调试日志，本目录下的文档聚焦于：
1. **全局架构审视**：单向分层治理、模块解耦、上帝文件治理、安全沙盒边界。
2. **唯物性能剖析**：内存常驻基线（RSS）、CPU 空闲唤醒率、IO 瓶颈、Token 吞吐开销。
3. **交互与体验演进**：WebUI 渲染帧率与触控稳定性、TUI 键盘响应质感、平台消息流一致性。
4. **模型纪律与协议设计**：提示词工程瘦身（Dev 模式轻量化）、上下文前缀冻结（KV 缓存命中）、工具调用参数自愈。

---

## 二、分析文档编写规范

所有在 `docs/analyse/` 下产出的分析与改进方案，必须严格恪守 Miyu 作者的核心工程公理：

### 1. 唯物实证（Radical Empiricism）
- **方案是嫌疑人，不是证据**：任何“建议优化”必须指出当前代码的具体位置（精确到 `file#line`）与存在的度量痛点（如耗时、内存泄漏风险、逻辑竞态）。
- **实测先行**：优化方案涉及性能/内存时，必须提供对比基准（Before vs Expected After），严禁“凭感觉优化”。

### 2. 前缀即契约（Prefix-as-Contract）
- 涉及模型提示词与工具调用的改进分析，必须评估对系统前缀缓存（Prompt Caching）的影响，严防因动态时间戳、乱序字段导致缓存击穿。

### 3. 模型面纯净性（Zero CJK on Machine Interface）
- 涉及面向模型的工具描述、参数摘要、错误回灌协议，一律规划为纯英文短句，防止中文机械语料诱发模型角色出戏（OOC）。
