## 2. 理念对照(每一步都要过)

| 理念 | 落到这里 |
|---|---|
| 前缀即契约 · 三份内容分离 | 编辑历史、改动视图是 **UI sidecar**,不注入模型上下文,不碰工具描述 |
| 权限由代码承担 | 读 diff、看改动、写文件、设工作区都按真实 principal 判路径;成员只到自己工作区,设工作区仅管理员 |
| 参数不是证词 | 「+N −M」取**实际落盘**的 diff,不取模型的 patchText——补丁可能部分失败,也可能被模糊匹配改写过 |
| 收口放唯一入口 | 采集点放在 `patch_preview.rs` 写入与删除预览处,不在各工具里各记一份;中转线那条路收进同一个函数 |
| 取证链不净化 | 落库存原始 unified diff 全文(有上限),不只存计数 |
| 先证明不修时现象出现 | 验收用 `git diff --numstat` 对账;先造一个「命令改文件」的反例,证明它不进编辑记录、且 UI 标注了来源 |
| 可测量 · low-footprint | 编辑器库的体积与内存实测后再选 |

## 3. 分步

依赖:**3.1 → 3.2 → (3.3 ∥ 3.4) → 3.5**。每步可单独交付。

### 3.1 编辑记录落库(地基)

- 新表(暂名)`turn_file_changes(turn_id, tool_id, seq, path, op, added, removed, diff, truncated, created_at)`。
- 写入收口处除了原来的字符串进度,再发一份结构化事件;`src/web/event_map.rs` 收到后落库。旧的 `__patch_preview__` 字符串**保留**——终端摘要还在读,AGENTS.md §2.3 双兼容。
- `path` 存相对工作区路径;diff 单条上限(建议 256 KB),超了 `truncated = true`,计数仍按全文算。
- 会话回合接口带 `file_changes` 摘要(路径、op、+/−);diff 全文按需另取。
- `未核实`:子代理里的编辑是否带着父回合的 `turn_id` 进来;中转线那条路要一起接。

### 3.2 回合结尾「改动了哪些文件」+ 侧栏 diff

- dev 会话助手气泡末尾一行可折叠:`改动 3 个文件  +42 −7`;展开后每行 `路径  +N −M`。
- 点某个文件 → 侧栏 diff 视图。渲染复用 `web/diff.js`,输入换成落库的真实 diff;视图里给「看改后全文」,跳到 file-links 的源码视图。
- 同一文件一回合改多次:合并成一行、计数累加,diff 按先后顺序列出。不自己算合并后的 diff——那是造一个从没落过盘的中间态。
- 与 `webui-delivery.md` §5 的产物 chip 放同一位置,视觉一致。

### 3.3 查看改动(会话级)

- 入口「查看改动」:本会话所有回合的编辑记录,按文件聚合,可按回合筛。
- 工作区是 git 仓库时加「git」页签:`git status` + `git diff`(工作区对 HEAD),标明「包含命令与手动改动」。
  与「编辑记录」页签并列,两个来源不混成一个数字。
- git 以 argv 调用,只读,只在工作区根内。
- 不做:回滚 / 撤销按钮——那是写入面,另议。

### 3.4 指定工作区

- 新建 dev 会话时、会话设置里各给一个「工作区」:输入框 + 最近使用 + 服务端目录浏览(只列目录)。
- 仅管理员可见;成员账号本来就被沙盒固定,不显示。
- 工作区进的是化石化的 runtime 块,不在稳定前缀里。但按 AGENTS.md §1.6 仍要**实测**:切换后连发两轮,看第二轮 `cache_read` 没有异常下降。
- `未核实`:回合进行中切换工作区的行为。
- **待问(2026-09-14 用户提出)**:dev 提示词要不要注入 `AGENTS.md`——是保持提示词精简、让模型自己发挥,还是注入项目约定?与 2026-09-13 的裁定「注入全文改成注入一句指路」一并决定。

### 3.5 内置编辑器

分两档:

- **A 只读工作台**:侧栏源码视图 + 高亮 + 跳行 + 文件内搜索 + 工作区文件树。「替代外部编辑器**读**代码」这部分,A 就覆盖了大头。
- **B 可编辑**,前提三条:
  1. 保存走 3.1 同一个收口,用户的改动也进编辑记录,`op` 标 `user`。
  2. 保存带打开时的内容 hash;文件在打开后被她改过就拒写,并显示两边差异,不静默覆盖。
  3. 仅管理员 + 与 file-links 同一套路径判定。
- 选型:CodeMirror 6(按需模块)vs 在现有 prism 源码视图上加 textarea。Monaco 数 MB,判不选。**体积与内存实测后再定。**
档位见 §4 第 3 条:第一版就能编辑(B)。

## 4. 裁定(2026-09-14,看过前端原型后)

1. 编辑记录**只在 dev 会话**显示,普通会话不显示。
2. 命令改的文件**按原型的做法**:编辑记录只收编辑工具,命令与手动改动由 git 页签补全。另加一条:**文件行都要带对应的文件类型图标**(编辑记录、查看改动、git 页签、文件树),复用 WebUI 现有的附件类型图标那一套,不另画。
3. 内置编辑器第一版**就能编辑(B)**(2026-09-14 先选了 A,随即改为 B):只读浏览 + 编辑保存。§3.5 B 的三条前提照做——保存走编辑记录同一个写入收口、打开后被她改过就拒写并显示差异、仅管理员。
4. **告诉她**:用户在工作台保存后,下一条消息尾部追加一条说明「用户改了 x 文件 +N −M」(纯追加,不动前缀);输入框上方给提示,可以点掉这一次。
5. 工作区目录浏览**不限定根**。
